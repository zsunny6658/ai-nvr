# aiNVR 导航入口收敛设计：摄像头卡片为一级入口（录像文件 / 事件）

> 状态：设计稿（v1，2026-11-23）。待拍板后实施。

***

## 1. 背景与问题

当前导航四页：**摄像头 / 事件告警 / 回放 / 设置**（桌面侧栏 + 移动底部导航同构）。用户反馈：入口太多且与使用心智不符——

- 「录像文件」藏在 回放页 → 文件窗格，且是**全部摄像头**的总列表，与"我想看某个摄像头的录像"的心智不符；
- 「事件告警」是全局页，单摄像头视角反而要靠筛选；
- 摄像头卡片才是用户最常驻的画面，但目前只有 预览 / 录像开关 / 自检 三个动作，回放与文件反而要离开卡片去别页选摄像头。

目标：**以摄像头卡片为一级入口组织"看、回、管"，全局页降级为汇总工具**。

## 2. 现状盘点（2026-11-23 代码）

| 现有入口 | 位置 | 内容 | 备注 |
|---|---|---|---|
| 摄像头卡片 | cameras tab | 快照预览 / 开始停止录像 / 自检 / 最近画面变动（最近 3 条快照） | 「查看全部」已跳事件页并按该摄像头筛选（gotoCamEvents，state.evPendingDid） |
| 事件告警页 | events tab | 设备/类型/状态/日期筛选、批量标记已处理、批量删除、清理糊屏/清空、未处理徽标 | 跨摄像头汇总能力 |
| 回放页 | playback tab | 摄像头下拉 → 时间轴回放 / 录像文件两窗格切换 | 文件窗格含全部摄像头分组 + recChips 快捷标签 + 批量删除/打包/在文件管理打开 |

## 3. 方案 A（推荐）：卡片一级入口 + 全局页降级汇总

### 3.1 摄像头卡片改版（核心）

操作区从 3+1 按钮重排为两行紧凑布局：

```
┌─────────────────────────────┐
│  [最近快照，点击=实时预览]      │
│  名称 · 休眠/在线徽标  · 录像中 │
│  [实时预览] [回放] [录像文件]   │
│  [开始录像] [自检] [更多 ▾]    │   ← 第二行低频操作
│  最近画面变动（最近 3 条快照）   │
│  查看全部 ›                   │
└─────────────────────────────┘
```

- **「回放」**：打开回放页并锁定该摄像头（复用 state.pb.did + loadTimeline(autoLatest)，从上一段末尾起播）；
- **「录像文件」**：打开单摄像头文件弹层（见 3.2）；
- 「开始录像 / 自检」收进第二行或「更多」菜单（移动端优先收纳，桌面可平铺）。

### 3.2 录像文件：唯一入口 = 卡片

- 新增**设备文件弹层**（或 cameras tab 内嵌面板）：仅显示该摄像头文件，复用现有 recRowHtml / 分组渲染 / 批量删除 / 打包下载 / SDK「在文件管理打开」全部能力；
- 数据层无改动：API `api/recordings?did=` 已支持按摄像头筛选；`recShown`/勾选本来就是按 did 的 Map/名称集合；
- 回放页的「录像文件」窗格**移除**（或降级为当前回放摄像头的只读快捷列表，不做总入口）；
- **跨摄像头总视图不消失，降级搬家**：设置 → 存储与录像 → 「全部录像文件管理」入口。理由：跨摄像头批量清理/空间盘点是**管理员低频操作**，放设置符合心智；已有折叠组零渲染（本日 91fe0bc）足以承受大列表性能。

### 3.3 事件：入口已有一半，补齐另一半

- 现状「查看全部 ›」已从卡片进入事件页并自动筛选该摄像头——**保留并强化**：
  - 从卡片进入时，事件页顶部显示「仅看：{摄像头名} ✕」胶囊，点 ✕ 一键回全部（比下拉筛选更直观）；
- **导航「事件」tab 去留给两个选项**：
  - **A1（推荐）**：保留但更名「事件汇总」，定位跨摄像头巡检（未处理徽标、批量处理、"今天家里发生了什么"——这些天然是跨设备需求，藏进单摄像头会失效）；
  - **A2（激进）**：移除 tab，全局事件汇总仅从**顶栏未处理徽标**进入（徽标本身已是全局事件入口）；移动端底部导航收敛为 摄像头 / 回放 / 设置 三项。
  - 若选 A2，批量标记/删除能力保留在徽标进入的汇总视图里，能力不丢失。

### 3.4 回放页联动

- 回放页摄像头下拉保留（页内快捷切换），但**不再是录像文件的总入口**；
- 时间轴回放与文件弹层互通：文件弹层「播放」→ 打开回放页并 seek 到该文件时间段（openPlayer 现有逻辑，增强为进回放页时间轴定位）。

## 4. 信息架构对比

| 能力 | 现状 | 方案 A1 | 方案 A2 |
|---|---|---|---|
| 看单摄像头录像文件 | 回放页→文件窗格（全部混排） | 卡片「录像文件」弹层 | 同左 |
| 跨摄像头批量清理 | 回放页文件窗格 | 设置→存储（管理员） | 同左 |
| 看单摄像头事件 | 事件页筛选 | 卡片「查看全部」+ 胶囊锁定 | 同左 |
| 跨摄像头事件巡检 | 事件 tab | 事件汇总 tab（更名） | 顶栏未处理徽标 |
| 底部导航项 | 4 项 | 4 项（更名） | 3 项 |

## 5. 实施拆分

| 阶段 | 内容 | 预估 |
|---|---|---|
| **P1** | 卡片加「回放」「录像文件」按钮（锁定摄像头）+ 单摄像头文件弹层（复用现有渲染/批量组件）+ 事件页「仅看」胶囊 | 1~1.5 天 |
| **P2** | 回放页文件窗格移除；跨摄像头文件管理搬家到设置→存储；卡片低频按钮收「更多」菜单 | 0.5 天 |
| **P3** | A1 更名「事件汇总」或 A2 移除事件 tab（等真机验证后拍板） | 0.5 天 |
| **P4**（可选远期） | 设备详情弹层聚合 预览/回放/录像/事件 四窗格，卡片成为完全唯一的设备入口 | 视 P1~P3 反馈 |

## 6. 风险与开放问题

1. **跨摄像头批量能力降级**：A2 移除事件 tab 后，"巡检全部未处理"只走顶栏徽标——徽标为 0 时入口消失，可接受（无未处理=无巡检需求）。
2. **文件弹层 vs 内嵌面板**：弹层（复用 overlayHistory 返回键栈）与飞牛 App 返回手势兼容更好，推荐弹层。
3. **SDK 宿主（fnOS 桌面）**：卡片按钮增多后移动端布局需真机验证；「更多」菜单复用 ev-more-actions 的 details 模式。
4. **共享看板/Webhook 不受影响**：板卡入口独立于本次收敛。
5. 旧习惯迁移：从回放页找文件的用户（如有）需要在设置页给出一处明确入口文案。

## 7. 结论与建议

- 录像文件：**卡片唯一入口**成立，全局视图降级到设置→存储（能力不丢、心智更顺）；
- 事件：**卡片入口已存在**（查看全部），全局页建议保留为「事件汇总」（A1），是否去掉 tab（A2）待真机用一阵再定；
- 回放：保持独立 tab（时间轴是重交互页面，不适合塞进弹层），但入口补到卡片上。
