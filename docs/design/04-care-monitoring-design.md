# aiNVR 看护守护功能（老人 / 儿童）调研与详细设计

> 状态：设计稿（v1，2026-11-23）。待评审后按 P1 → P2 → P3 分期实施。

***

## 1. 背景与目标

### 1.1 业务场景

家庭摄像头第二大用途是**看护**：独居/日间独自在家的老人、婴幼儿与学龄儿童。当前 aiNVR 的事件体系以"安防"为核心（人形/车辆/宠物移动侦测），对"人一直在这里、但发生了需要家人知道的事"这类**状态型/时间型**需求没有表达力。看护功能在现有 AI 管线上叠加**规则引擎层**，把检测流变成守护告警。

### 1.2 竞品调研结论（2026-11 检索校准）

| 能力 | 萤石（海康） | 小米/米家 | 360 | 海马爸比/亲宝宝 | aiNVR 现状 |
|---|---|---|---|---|---|
| 人形/宠物检测 | ✅ 自研模型 | ✅ 本地 AI | ✅ | ✅ | ✅ ONNX refine |
| 跌倒检测 | ✅ 高端型号，自研模型 | ⚠️ 少数新品 | ❌ | ⚠️ 部分 | ❌（可做启发式） |
| 婴儿哭声侦测 | ⚠️ 部分型号 | ✅ | ✅ | ✅ 主打 | ❌（音频轨已有） |
| 电子围栏/区域划定 | ✅ | ✅ | ✅ | ✅ | ❌（事件无区域概念） |
| 异响感知 | ✅ | ✅ | ✅ | ✅ | ❌ |
| 徘徊/逗留检测 | ✅（门锁侧） | ✅ 室外机 | ✅ | ❌ | ❌ |
| 长时间无活动提醒 | ⚠️ 少见 | ❌ | ❌ | ⚠️ 离床 | ❌ |
| 双向通话/一键呼叫 | ✅ 主打 | ✅ 微信通话 | ✅ | ✅ | ✅ 已有对讲喊话 |
| 隐私遮蔽 | ✅ 软件 | ✅ 物理遮蔽 | ✅ | ✅ | ❌（休眠可代替） |
| 电话/强提醒 | ✅ 付费 | ✅ | ✅ | ✅ | ❌（SMTP/MQTT 已有） |

**差异化定位**：竞品的看护 AI 全部绑定**特定摄像头硬件 + 云端/芯片端**，跨品牌用户无法享受；aiNVR 的看护能力跑在**NAS 本地**，任何接入米家的摄像头通用，事件可进 HA 联动、可邮件/MQTT 分发，且 GPL 免费无限路数。主打卖点：**"旧摄像头白嫖看护黑科技 + 数据不出家门"**。

### 1.3 设计目标与约束

1. **零新增依赖起步（P1）**：规则引擎只消费现有 EventStore 事件流（person/motion/vehicle/pet + 检测框），不动取流与推理链路。
2. **误报优先级高于漏报抑制**：看护告警的受众是"不在现场的家属"，冷却与分级机制防打扰，但关键告警（跌倒/哭闹）宁可重复提醒。
3. **休眠联动**：摄像头休眠（MiotSleepService）期间产生的"无活动"一律不算异常，避免唤醒设备与误报。
4. **一切本地**：规则、模型（P2）、快照均不出网；通知渠道复用现有 NotifyService/SMTP/HaMqttService。
5. **每摄像头独立配置**：看护模式与规则按 did 存储，副镜头（DualLens.SUFFIX）跟随主镜头。

## 2. 功能定义

### 2.1 模式

每台摄像头三种预设模式 + 自定义：

| 模式 | 适用 | 预置启用规则 |
|---|---|---|
| **关闭** | 默认 | 无 |
| **老人看护** | 客厅/卧室/卫生间视角 | 无人活动提醒、跌倒初判（提示级）、夜间活动、逗留检测 |
| **儿童看护** | 婴儿房/游戏区/门口 | 哭声检测（P2）、区域入侵、离床/出画提醒、夜间活动 |
| **自定义** | 进阶用户 | 任选规则逐条配参 |

### 2.2 规则清单与分期

| # | 规则 | 判定逻辑 | 分期 | 误报风险 |
|---|---|---|---|---|
| R1 | **区域入侵（电子围栏）** | person 检测框与配置区域相交 ≥ N 秒 | P1 | 低 |
| R2 | **看护时段活动** | 时段内（如 22:00–06:00）出现 person 事件 | P1 | 低 |
| R3 | **逗留检测** | 区域内 person 持续存在 ≥ N 分钟 | P1 | 低 |
| R4 | **长时间无活动** | 看护时段内连续 M 分钟无 person/motion 且设备未休眠 | P1 | 中（需休眠联动） |
| R5 | **跌倒初判（提示级）** | person 框纵横比突变 + 框中心高度骤降 + 低位持续 ≥ N 秒 | P1.5 | 高（仅"提示级"文案） |
| R6 | **哭声/呼救声检测** | 音频流分类（YAMNet 类模型 ONNX） | P2 | 中 |
| R7 | **姿态跌倒检测** | 轻量姿态模型关键点比例判定 | P2/P3 | 中 |
| R8 | **行为识别**（攀爬、翻越围栏） | 时序姿态/动作分类 | P3 | 高 |

P1 全部为事件流上的纯规则计算，无新增模型、无新增推理负载；P2 引入两条新分析管线（音频分类、逐帧姿态），需独立资源评估。

## 3. 总体架构

```
摄像头 RTSP/米家流
   │
MotionDetector ──► EventStore(motion) ──► AiDetectService(ONNX refine: person/vehicle/pet + boxes)
                                              │
                                              ▼
                                   EventStore.refine() 原位更新
                                              │
              ┌───────────────────────────────┼──────────────────────────────┐
              ▼                               ▼                              ▼
      SnapshotArchiveService           HaMqttService                 NotifyService
      （现有监听者，不动）               （现有监听者，不动）            （现有监听者，不动）
                                              │
                                              ▼  新增监听（addRefineListener 同款机制）
                                   ★ CareRuleEngine（新，单线程队列）
                                        │ 逐事件跑该 did 启用的规则
                                        ▼
                                   CareEvent 决策（冷却/分级/静默窗口）
                                        │
                          ┌─────────────┼─────────────┐
                          ▼             ▼             ▼
                    EventStore       NotifyService   HaMqttService
                    （care 事件）     （分级通知）     （care 传感器）
                          │
                          ▼
                    SnapshotArchiveService（care 快照归档复用）
```

关键点：

- **CareRuleEngine 是消费者不是拦截者**：挂在 refine 回调上（同 SnapshotArchiveService 的 `EventStore.addRefineListener`），AI 管线零改动。
- 规则引擎内部**单线程串行**（同 AiDetectService 队列风格），规则计算是 O(规则数 × 框数) 纯内存运算，可忽略。
- 跨事件时间状态（逗留、无活动、纵横比序列）按 `(did, ruleId)` 维护在内存 Map；重启后从 EventStore 近 1 小时事件重建（P1 可简化为重启清零、重新累计）。
- **R4 无活动**由引擎内 30s 定时器驱动（不依赖事件到来）：检查"现在 − 最后活动时间 > M 分钟"且 `MiotSleepService` 报告该设备未休眠且在时段内。
- **R6 哭声检测（P2）**：新 `AudioClassifyService` 从 RTSP 音频轨解 PCM（对讲喊话链路已有 G.711/PCM 解码经验可复用），滑窗 1.5s 送 ONNX 分类；仅在启用 R6 的摄像头运行。

## 4. 数据模型

### 4.1 设置存储（AppSettingsStore，IMPORTABLE_KEYS）

```
KEY_CARE_ENABLED   : bool    全局开关
KEY_CARE_PROFILES  : JSON    did → profile
```

```json
{
  "did-xxx": {
    "mode": "elder",              // off | elder | child | custom
    "rules": [                     // mode=custom 时逐条；预设模式由后端展开默认参数
      {
        "id": "zone",
        "enabled": true,
        "zone": [[0.6,0.0],[1.0,0.0],[1.0,0.6],[0.6,0.6]],  // 归一化多边形（顶点 ≤ 12）
        "minSeconds": 3,
        "label": "厨房门口"
      },
      {
        "id": "schedule",
        "enabled": true,
        "from": "22:00", "to": "06:30"
      },
      {
        "id": "dwell",
        "enabled": true,
        "minutes": 10
      },
      {
        "id": "inactivity",
        "enabled": true,
        "minutes": 90,
        "from": "08:00", "to": "22:00"
      }
    ],
    "notifyLevel": "warn"          // info | warn | critical：低于该级的 care 告警只记事件不推送
  }
}
```

- 副镜头不独立配置：按主镜头 did 归一。
- 预设模式（elder/child）下 `rules` 由后端按默认参数生成并允许前端改参后落回 JSON（自动转为 custom？——否：保留 mode，参数覆盖单独存，避免用户改一个参数整个变成"自定义"失去语义）。

### 4.2 事件（EventStore 扩展）

- 新事件类型 `care`，`refine` 后子类型为规则 id（care-zone / care-schedule / care-dwell / care-inactivity / care-fall / care-cry）。
- 事件 `detail` 附带：规则名、区域标签、置信度说明、快照路径（复用 SnapshotArchiveService 的归档产物路径回填机制）。
- 事件页新增筛选分组「看护」，独立于安防事件；看护事件在时间轴上用独立颜色标记。

### 4.3 告警分级与冷却

| 级别 | 规则 | 冷却（同一 did+规则） | 通知行为 |
|---|---|---|---|
| info | 逗留、区域入侵 | 10 分钟 | 只记事件 + HA |
| warn | 时段活动、无活动、哭声 | 15 分钟 | 事件 + 推送/邮件 |
| critical | 跌倒初判、哭声（连续 2 窗命中升级） | **5 分钟，且 30 分钟内可重复 3 次** | 事件 + 推送 + 邮件 + HA alarm |

- 每条规则独立冷却计时器；critical 在冷却期后仍命中则再报（跌倒场景"宁可吵"）。
- **静默窗口**：用户在事件页对该 care 事件点"我知道了"后，该 did 该规则 60 分钟静默（防连续打扰，设置页可关）。

## 5. 各规则实现要点

### 5.1 R1 区域入侵（P1）

- zone 为归一化多边形顶点数组；person 框（AiDetectService 输出的 0~1 归一化 [y1,x1,y2,x2]）与多边形做**框底边中点**（脚点 `(x1+x2)/2, y2`）命中判定——脚点比框相交更符合"人进入区域"的直觉，减少画面前景遮挡误报。
- 连续命中 ≥ minSeconds 才告警：维护 `(did, zoneId)` 的首命中时间，事件流中断（非 person 或脚点出区）超 2s 重置。
- 前端设置页：摄像头当前快照上叠加可拖拽多边形编辑器（画布标点，最少 3 点）。P1 可先提供**矩形/网格九宫格**快捷选择 + 完整多边形后置，降低前端工作量。

### 5.2 R2 看护时段活动（P1）

- 时段跨零点处理：`from > to` 视为跨天（22:00–06:30）。
- 仅消费 refine 后 person 事件（vehicle/pet 不触发）；休眠期间事件本就不会产生，天然兼容。

### 5.3 R3 逗留检测（P1）

- R1 的超时版：脚点持续在任意启用区域/或全画面 person 存在 ≥ minutes。门口/玄关场景防"快递员长期停留"与"老人起夜跌倒无人发现"两类需求。

### 5.4 R4 长时间无活动（P1）

- 引擎 30s 定时器：`now − lastActivity(did) > minutes` 且在时段内 且 `MiotSleepService.sleeping(did) != true` 且设备在线（DeviceProbe/lanReachable）。
- lastActivity 来源：该 did 最近 person/motion 事件时间（EventStore 查询）。
- **告警语义**："已 90 分钟未检测到活动，建议查看"；家属确认后点"一切正常"重置计时。⚠️ 边界：摄像头休眠重启后 lastActivity 用休眠开始时间修正，避免"休眠 2 小时醒来立刻误报"。

### 5.5 R5 跌倒初判（P1.5，提示级）

纯几何启发式，零新模型：

1. 维护滑动 10s 窗口内 person 框序列；
2. 条件 A：纵横比（宽/高）由 <0.8 突变为 >1.3（站立→横躺）在 ≤2s 内完成；
3. 条件 B：框中心 y 由 <0.6 升至 >0.75（画面下部）；
4. 条件 C：满足 A+B 后，低位 person 持续 ≥ 20s 且位置基本不动（位移 < 5% 画面宽）；
5. 命中发 **critical 但文案明确"可能是跌倒，请人工确认"**。

已知局限（写进 UI 文案）：坐姿、趴睡、画面下半被遮挡均会误报/漏报；此规则是 P2 姿态模型落地前的"占位能力"。

### 5.6 R6 哭声/呼救检测（P2）

- 模型：YAMNet（Google，521 类含 Crying/Cry of infant，939×1 采样 16kHz）或更轻量的 PANNs-lite；导出 ONNX，int8 量化后约 4MB。
- 输入：RTSP 音频轨解 PCM → 16kHz 单声道重采样（对讲链路已有重采样代码）→ 0.975s 滑窗 stride 0.5s。
- 判定：单窗 crying 分数 > 0.4 触发 warn；连续 3 窗（≈1.5s）> 0.5 升级 critical（呼应分级表）。
- 资源：每路启用摄像头的音频解码 + 推理约 <5% 单核（YAMNet 量级），5 路以内可接受；超限由设置页提示按路数取舍。
- 呼救/尖叫与哭声共用模型多标签输出，文案区分"疑似哭声/疑似呼救"。

### 5.7 R7 姿态跌倒检测（P2/P3）

- 模型候选：MoveNet Thunder（17 关键点，轻量）/ RTMPose-t；ONNX int8。
- 管线：LiveFrameService 取实时帧（现有服务，1~2 fps 足够）→ 人体检测框（复用 AiDetectService）→ 裁剪 ROI → 姿态推理 → 关键点时序规则（躯干角度、头脚相对高度）。
- 每 fps 1 帧单路推理成本可控，但模型体积与精度需先离线用公开数据集（UR Fall / Le2i）验证，**不达 90% 召回不上线**，未上线期间 R5 提示级兜底。

## 6. UI 设计

### 6.1 设置页「看护守护」卡片（set-card-wide）

- 全局开关 + 按摄像头列表配置（复用现有 q-row 行样式）：模式单选（关/老人/儿童/自定义）、每行展开规则参数。
- 区域编辑：P1 用九宫格勾选（快照上 3×3 网格，勾选格子合成矩形 zone）；多边形编辑器列为 P2。
- 保存即生效：`PUT /api/settings/care` → AppSettingsStore + CareRuleEngine 热更新（重建规则表，不重启）。

### 6.2 事件页

- 顶部筛选新增「看护」页签（与全部/移动/人形并列）。
- care 事件行显示：规则名、分级徽标（info/warn/critical 三色）、区域标签、确认按钮（"我知道了"→静默窗口）。

### 6.3 通知文案模板（NotifyService）

- 无活动：`【看护】{摄像头名}已 {M} 分钟未检测到活动（{时段}），建议看一眼`。
- 跌倒初判：`【看护·请立即确认】{摄像头名}画面疑似有人跌倒`。
- 哭声：`【看护】{摄像头名}检测到疑似{哭声/呼救}（连续 {n} 秒）`。
- 邮件模板沿用现有 SmtpMailer；HA MQTT 主题 `{base}/care/{did}`，payload 含 rule/level/label/snapshotPath。

## 8. 风险与开放问题

1. **R4"无活动"的时钟语义**：夜班老人白天补觉 vs 白天离家无人——时段参数能否覆盖真实作息，需要真机灰度用户反馈；考虑加"当日已确认正常"按钮重置当日计时。
2. **米家摄像头休眠期间音频轨是否中断**：R6 需真机确认休眠时 RTSP/流的行为（大概率断流），休眠期间 R6 静默即可，与 R4 同理。
3. **副镜头**：AI 检测当前是否覆盖副镜头（DualLens 第二镜头进主分支待真机验证）——P1 规则引擎按主镜头配置生效于副镜头事件，需验证副镜头是否有 refine 事件。
4. **哭声模型版权**：YAMNet Apache-2.0 可商用；若自训需标注数据，P2 前置调研工作量 +0.5 天。
5. **隐私**：看护快照含家庭成员画面，归档目录沿用 SnapshotArchiveService 但在设置页明确提示 retention（沿用现有保留策略清理）。
